## Evidence and exact cause

The user supplied Android trace observations: pass 8 completed every stage, PASS_DONE and DRAIN_END; about 25 seconds later a game-triggered request increased revision 7 to 8 and restarted pass 9 at roster. FA took approximately 17.2 s, Trade 23.3 s and Waiver/action 2.2 s. The completed trade funnel had 6804 evaluations, 3 fully scored candidates, 0 admitted trades and status CURRENT. These numbers describe the supplied observation, not newly measured device performance. The exact two game response bodies were not supplied, so semantic equivalence of that specific Android update is not asserted.

Code path: app.js scheduleSeasonActualRefresh schedules a 60-second foreground update. refreshSeasonActualScores calls refreshSeasonGameContext even before its actual-score cache shortcut. refreshSeasonRankings is the second caller. refreshSeasonGameContext polls LIVE/missing-state/past-kickoff PREGAME contexts after 60 seconds and other contexts after 15 minutes. The endpoint is /api/nfl-week-context. game-context-v1.js buildSnapshot derives snapshotId and envelope/game verification/expiry timestamps from local acquisition time. Identical source content can therefore acquire a new identity.

Before repair every successful fetch unconditionally persisted that snapshot and called queueSeasonRerender(false,'game'). That increments seasonRenderRevision, clears all decision surfaces and lastPostDraftPairs, and starts rerenderPostDraftFromContext from roster through lineup, FA, Trade, Waiver and Action Board. There was no content comparison or per-stage dependency invalidation. In-flight passes fail their existing identity/revision/deadline guard and require a successor. A network exception persisted a failure snapshot but omitted the render invalidation request.

## Dependency scope and bounded correction

Game context is shared decision input: seasonDisplayContext feeds presentation and derived player evidence; seasonProjectionLineup consumes locks; seasonCurrentWeekEligibility and seasonDstEvidence gate players/special teams; seasonWeeklyPlayerLabel and seasonGameContext display provenance/context; prepareSeasonDecisionEvidence consumes environment, matchup, weather, lock and expiry information. FA and Trade reuse those player/lineup dependencies. No proof permits reuse of only FA or Trade after a real context change, so no partial stage cache is added.

seasonGameContextEquivalent permits a no-op only when both snapshots are valid in the same season/week at comparison time; game and verified weather/odds evidence are still fresh; PREGAME is not past kickoff; all fields other than the explicitly identified locally generated snapshotId/envelope/game verification and expiry fields compare exactly. Nested source timestamps, odds, weather, source URLs, event identity, kickoff, status, coverage, rejections and unknown fields remain compared. Replacement local timestamps may not regress. JSON property/array order differences may cause conservative extra recomputation, never extra admission.

On equivalence the old snapshot bytes are retained and returned. Its identity, original freshness/deadlines, existing expiry timer and model bindings are not extended, rewritten or reauthorized. No new revision or surface clearing occurs; GAME_UNCHANGED is recorded in the existing bounded trace. Expiry still invalidates at the existing deadline. This can mean another acquisition on a later scheduled poll because the old verifiedAt remains unchanged; this repair removes unnecessary recomputation, not provider polling.

Changed or invalid evidence continues through full invalidation. Network exceptions now also request that invalidation after the existing failure-snapshot persistence path. Persistence still uses the repository's existing quota-safe auxiliary helper; general storage-failure recovery is not redesigned in this change. Flight coalescing and response admission now bind to the captured lastDraftContext object as well as season/week; replaced contexts, including another league in the same week, cannot accept the old response.

Visible obsolete recommendation lists are cleared on real invalidation. No stale recommendation is retained on screen or promoted as actionable. The prior trade-funnel object may remain in the diagnostic export; its legacy CURRENT label binds weekly/Boone/live timestamps and age, not game revision, and must not be interpreted as action authorization. This repair does not reuse that object. Zero admitted trades can be a correct final evidence-based HOLD.
